**Mission:** Complete the entire frozen GDD scope in this ONE assignment. Do not send routine design, visual-POC, engineering or acceptance questions back to the owner.

## Agent authority and success condition

The owner has already decided the target experience, content, visual quality, applicable platforms and release scope in the FINAL GDD. You own engineering strategy, internal task order, asset pipeline, technical alternatives preserving observable behavior, targeted test design, self-correction, recovery and verified publication **where separately and explicitly preauthorized in the GDD**.

Do not turn implementation into repeated owner review rounds or ask for approval of intermediate proofs of concept. Use private technical/visual spikes if needed. Fix defects and retest without asking. Do not reduce requirements, remove content, weaken accessible behavior or silently degrade art to finish faster.

## Preflight — internal, not a human milestone

1. Inspect repository, current branch, actual hosting configuration, deployment side effects, existing source, licenses/credentials availability, FINAL GDD and pinned applicable AICP/UGDS. If a source cannot be retrieved, use an approved immutable copy; do not invent its contents. Block only genuinely affected work.
2. Identify any impossible release-critical GDD conflict; exhaust documented safe fallbacks before escalation. Do not pause routine work for a ceremonial Offer.
3. Use a dedicated work branch. Safely push recoverable editable-source checkpoints during consequential work; record last verified remote SHA. No force pushes, secret exposure, silent settings changes or protected-branch bypass.
4. If hosting, branch protection or publication permissions are missing, complete safe development and produce a ready PR/release artifact, honestly marking what remains blocked.

## Autonomous execution

1. Implement all required mechanics/features, assets, UI, localization/accessibility and persistence as specified. Build internal vertical slices only when they de-risk completion; **no owner-facing POC approval**.
2. Inspect running UI/game and visual output against **observable GDD criteria**. Correct integration, animation, alignment, contrast and responsive issues.
3. Run risk-based relevant unit/logic, production-build, real browser success + failure/retry, declared-device/input/language, targeted a11y and visual checks. Expand where warranted; never chase a target test count.
4. Repeat correction and verification until frozen release-critical criteria pass, or an actual hard blocker is isolated. Mark any check not run as Not Verified; do not claim a human aesthetic sign-off.
5. Commit and push final code and reproducible assets. If merge and deployment are explicitly preauthorized, follow existing repository/CI rules and **verify actual public gameplay/use** at the designated URL. If Possibility was independently preauthorized, follow its current catalog/host rules and verify that entry separately.
6. Complete with one final report. Do not ask the owner to open another phase simply because further ideas are possible.

## Hard-stop protocol (only if unavoidable)

Escalate only when AICP v2 §6 applies: material impossible design deviation, exhausted fallback, cost/account/security/privacy/license issue, inaccessible credentials/branch protections, or unapproved public target. Continue independent safe tasks. Raise **one narrow question** with a diagnosis, already-tried alternatives, safest proposed course and exact blocked operation. Never infer owner consent from silence.
