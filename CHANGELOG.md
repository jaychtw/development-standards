# Changelog

All notable changes to the Universal Game Development Standard (UGDS) are recorded here. Use semantic versions and pin a release tag or commit SHA in each game project.

## [AICP 1.4.0] - 2026-11-03

### Simplified
- Added risk-calibrated routine, bounded and exploratory execution modes; no new approval ceremonies.
- Made escalation exception-driven within an already authorized commitment.
- Established documentation economy and proportional evidence/verification expectations.
- Updated Codex brief, conversation starter, project-state and GDD templates to avoid boilerplate and duplicative records.

### Unchanged
- UGDS v1.0.0, existing project pins, owner creative/financial/release authority, checkpoints, recovery protections and honest verification requirements.

## [AICP 1.3.0] - 2026-11-03

### Added
- Risk-proportionate recovery-ready checkpoints and concise repository recovery pointers for active work.
- Explicit failed-session recovery procedure reconciling Git state, handoff claims, tests and owner authority.
- Optional independent reconstruction/clean-checkout verification at meaningful gates.
- Focused recovery guidance in conversation starter, Codex brief and project-state templates.

### Notes
- Responds to recurring transient cloud-workspace losses; no new paid backup service or routine approval ceremony.
- UGDS v1.0.0 and existing project pins are unchanged. Safe development-branch pushes remain distinct from merge and deployment.

## [AICP 1.2.1] - 2026-10-31

### Added
- Default Codex working-branch synchronization with meaningful intermediate and final remote checkpoints.
- Deployment, cost, secret and conflict safeguards plus independent backup handling when pushing is blocked.
- First-instruction reinforcement in the Codex brief and conversation starter, alongside reading adopted AICP.

### Notes
- Development pushes do not authorize acceptance, merge, release or deployment.
- UGDS v1.0.0 and existing project pins remain unchanged; explicit local-only exceptions are respected.

## [AICP 1.2.0] - 2026-10-31

### Added
- Proportionate Explore → Offer → Execute → Confirm & Close collaboration lifecycle with an explicit commitment gate.
- Codex feasibility assessment and counteroffer role before high-uncertainty implementation.
- Evidence-gated technical spikes, diagnostic feedback routing, milestone acceptance and separate follow-up commitments.
- Codex brief fields for Offer-stage evidence, owner commitment and closure outcomes.

### Notes
- AICP collaboration update only; UGDS v1.0.0 and existing project pins/acceptance criteria remain unchanged.
- Does not authorize implementation, merge, release, deployment, new costs or retroactive adoption.

## [AICP 1.1.0] - 2026-10-29

### Added
- Lightweight end-of-cycle retrospective as a default collaboration practice.
- Evidence-based lesson classification and promotion rules for AICP, UGDS, project records and technical references.
- Proportionate AI initiative and change-control limits to reduce owner coordination burden.

### Notes
- No automatic revision for every development cycle; no background activity promised.
- UGDS v1.0.0 and existing project acceptance criteria remain unchanged.

## [AICP 1.0.1] - 2026-10-29

### Clarified
- Explicitly identify https://github.com/jaychtw as the default discovery namespace for the owner's projects.
- Prioritize approved GDDs and design decision records when reconstructing intended product behavior.
- Require agents to verify access and disambiguate repositories rather than assuming universal visibility.

### Notes
- UGDS 1.0.0 and individual project acceptance criteria remain unchanged.

## [AICP 1.0.0] - 2026-10-29

### Added
- AI Collaboration & Continuity Protocol for context reconstruction, decision preservation, approval gates and agent handoffs.
- Project state and conversation-starter templates, plus a central README.

### Notes
- AICP is independently versioned; UGDS remains unchanged at 1.0.0.
- No retroactive adoption or game acceptance changes.

## [1.0.0] - 2026-10-23

### Added
- Universal baseline for bilingual English/Traditional Chinese games with live switching.
- Desktop and mobile interaction, responsive layouts, accessibility, and recovery expectations.
- Mandatory visual production standard distinguishing concept references, functional prototypes, and production-ready artwork.
- Gameplay integrity, local persistence when applicable, performance, and honest fictional framing.
- Automated engine, browser, balance, accessibility, release, and QA evidence requirements.
- Clear creative-director/Codex responsibilities, escalation, exceptions, and version pinning.
- Reusable GDD and Codex brief templates.

### Notes
- Existing games are not retroactively certified.
- Project-specific requirements and approved exceptions must be recorded in each project's GDD or acceptance record.
